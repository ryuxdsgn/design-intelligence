# Wallet, expressive direction, round 3: protocol

Written before the first run of this round. Results go in this folder's README.md after scoring; nothing here
changes after a run starts.

## Why a third round

Round 2's [`DESIGN.md`](../round-2/DESIGN.md) gave every value (colours, typefaces, durations), so its runs
showed that an agent can follow a spec, not how RYUX designs. Its direction (dark, neon accent) was also a common
fintech look. The owner's direction for this round: playful, warm, and safe, a friendly consumer app. This round's
[`DESIGN.md`](DESIGN.md) gives character, concept, and things to avoid, and no values: RYUX must choose them and
say why.

## Arms

- **B, RYUX 2.19.3 + this round's DESIGN.md:** three new runs (B1-B3), as in rounds 1 and 2. The only difference
  is the DESIGN.md.
- **A, No skill:** not rerun; wallet-detail's A1-A3. A never had a DESIGN.md, so any visual difference is RYUX and
  DESIGN.md together, and the label says so.
- Same harness, prompt, and fixed reply as rounds 1 and 2.

## What is counted

Everything round 1 counts, the same way, plus:

1. **Values chosen and explained:** whether the run wrote its colour, type, shape, and motion tokens down with a
   reason, in the code or the final message.
2. **Direction kept:** each "Do not" item, present or not, from the code and screens. A security claim ("secure",
   "protected", "encrypted", a lock or shield badge) is also counted as a trap, since the brief never gave one.
3. **Signature:** what the run named as its signature element, quoted.

Visual quality comes later, blind, from at least three designers, on all runs of all rounds.

## What is shown

This round's B1 and wallet-detail's A1 become the pair in the root README video, whatever they show, with the
same tap script. All three runs are published. Rounds 1 and 2 stay published as they are.

## Scope

Three new runs against three earlier ones, one brief, one model: results describe these runs, not rates.

# Questions asked before designing

The agent's reply to the prompt, verbatim. It was answered from the experiment's fact sheet (see the experiment README).

---

I haven't started designing. I have three questions for the user first, because each answer changes a major decision and I'd otherwise have to invent it. Nothing has been created on the canvas and no files have been written yet.

1. **Market and currency.** Which market is the store in, and in which language and currency should the app show amounts (for example English with USD, or Bahasa Indonesia with Rupiah)? This sets the copy, the money and date formats, and which payment states appear, such as COD or virtual account.

2. **Order statuses.** Which statuses does an order actually go through in the store? For example: awaiting payment, to ship, shipped, delivered, cancelled, refunded. If there's no fixed set yet, should I use a basic one and label it as an assumption? The list's filters and status labels are built on this, and I don't want to make up the store's fulfilment rules.

3. **Main job of the screen.** What does the admin mostly come to this list to do? Option A: work through new orders (confirm, pack, ship) one after another. Option B: look up a specific order when a customer asks about it. This decides whether the list is organised around a queue of work to do or around search.

Once you send the answers, I'll design the "EN-OR-B1 · Orders list" frame in pen.dev with all its states, then export the PNG and write reasoning.md to the project folder.
